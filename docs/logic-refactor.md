## Как теперь устроена отправка заявок

`src/lib/leads.ts`:
- `buildLeadPayload()` — payload: `kind`, `contact`, `message`, `topic`, `areaM2`, `floors`,
  `panelsApprox`, `source`, `page`, `submittedAt`, `elapsedMs`, `honeypot`;
- `validateContact()` — телефон (10–15 цифр), `@username` или email; понятная ошибка;
- `isLikelyBot()` — honeypot заполнен **или** отправка быстрее 900 мс;
- `submitLead()` — `POST` c `Content-Type: application/json`, таймаут 12 с,
  результат строго по HTTP-статусу:
  - `success` — только 2xx (опционально `{id}` из JSON-ответа);
  - `error` — `http` (4xx/5xx), `network`, `timeout` — с честным текстом для пользователя;
  - `unconfigured` — адрес приёма не задан: **ничего не выдумываем**, показываем
    «Отправка сейчас недоступна», в консоль — предупреждение для интегратора.

### Куда уходят заявки (нужно решение заказчика)

Адрес приёма задаётся двумя способами, приоритет — рантайм:

1. `window.ABG3D_LEADS_ENDPOINT = 'https://…'` — до загрузки скрипта виджета (удобно при встраивании);
2. переменная сборки `VITE_LEADS_ENDPOINT=https://…`.

Пока адрес не задан, формы **честно сообщают, что отправка недоступна** (истинного канала нет,
а фальшивую галочку виджет больше не рисует). Кандидаты канала: вебхук в CRM ABG,
Telegram-бот через прокси-эндпоинт (токен бота в браузер выносить нельзя), SMTP-шлюз.

## Осознанные компромиссы и что осталось

- **Адрес приёма заявок не выбран** — это решение заказчика (см. выше). До него формы работают
  корректно, но заявки не доставляются, и виджет об этом честно говорит.
- Значения полей формы сохраняются при закрытии (удобно при ошибке/повторе); сбрасывается
  только состояние отправки и honeypot.
- `?open=` открывает модалку при загрузке; крестик не правит URL, поэтому F5 откроет её снова.
- `select-none` на корне приложения остаётся: внутри модалок добавлен `select-text`, но текст
  3D-колаутов и рельсов по-прежнему не выделяется (это к задаче по вёрстке).
- Мёртвый проп `currentMode` у `LeftAnatomyRail` и `scrollStoryProgress` у `PanelScene`
  не трогали — файлы в зоне задач по вёрстке/3D.
- Публичного API (`window.ABG3D.*`, `postMessage`) и примера встраивания пока нет — вне рамок
  этой задачи (нужно решение «iframe или скрипт + API»).
