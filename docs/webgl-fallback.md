# ABG3d — фолбэк, когда WebGL недоступен (kanban t_69dc6f99)

Дата: 18.09.2026. Остаточный дефект приёмки `t_2045b58e` (пункт P0-1: «внешний CDN в
критическом пути») — на любом устройстве без WebGL виджет показывал **живые кнопки и
пустую сцену**: ни сообщения, ни 2D-чертежа, ни способа повторить попытку.

## Почему так было

`<Canvas>` из R3F создаёт `WebGLRenderer` в своём эффекте, а не в рендере. `SceneErrorBoundary`
ловит ошибки рендера дочерних компонентов, но отказ создания рендерера происходит в эффекте
самого `<Canvas>` — и сцена просто оставалась пустым прямоугольником. Потеря контекста на лету
(`webglcontextlost`) не бросала ошибку вообще — three молча прекращал рисовать.

## Что сделано

| Слой защиты | Где | Что закрывает |
|---|---|---|
| `probeWebGLSupport()` — до монтирования `<Canvas>` | `src/utils/webglSupport.ts` | WebGL нет вообще (старый Android, корпоративная политика, выключенный аппаратный рендер). При `unsupported` `<Canvas>` не монтируется, сразу показывается `SceneFallback` |
| `SceneErrorBoundary` | `src/components/Panel3D/SceneErrorBoundary.tsx` | Ошибки рендера/шейдеров/загрузки внутри `<Canvas>` |
| `WebGLContextGuard` — слушает `webglcontextlost` на канвасе R3F | `src/components/Panel3D/PanelScene.tsx` | Потеря контекста на лету (сброс драйвера, выгрузка вкладки в фон) |
| `SceneFallback` — общий 2D-фолбэк | `src/components/UI/SceneFallback.tsx` | Единый вид для всех трёх исходов: плашка «3D недоступно», причина, `FallbackBlueprint` (интерактивный 2D-разрез), честное сообщение и кнопка «Повторить 3D» |

Кнопка «Повторить 3D» заново пробует WebGL и перемонтирует сцену с новым канвасом
(`key={sceneKey}`); если WebGL так и нет — фолбэк остаётся на месте, пустоты не появляется.

Побочные правки раскладки: пока сцены нет, 3D-only оверлеи (`stage-controls-dock`,
HUD «512px Hi-Res карты», док «Сечение») скрываются — без сцены они бессмысленны и садились
на кнопку «Повторить 3D». У фолбэка жёсткие вертикальные отступы (`pt-[6.75rem]/sm:pt-[7.25rem]`,
`pb-[5.5rem]/lg:pb-12`), чтобы содержимое не уезжало под капсулу режимов и мобильный экшен-бар.

## Проверка (bun, локальная сборка, CDP)

WebGL отключался перехватом `HTMLCanvasElement.prototype.getContext` через
`Page.addScriptToEvaluateOnNewDocument` + перезагрузка. Потеря контекста — реальным
`WEBGL_lose_context.loseContext()` на канвасе живой сцены.

- `bun run lint` (tsc --noEmit) — чисто; `bun test` — 42 pass / 0 fail (7 новых тестов пробы);
  `bun run build` — зелёный.
- WebGL выключен: во всех вьюпортах (390×844, 768×1024, 1024×768, 1366×900, 756×488) — канваса
  нет, виден `FallbackBlueprint`, плашка «3D недоступно» и кнопка «Повторить 3D» в кадре;
  0 наложений с оверлеями (проверка ректов DOM).
- Клик по слою в 2D-чертеже выделяет слой (открывается док слоя) — фолбэк интерактивный.
- «Повторить 3D» при выключенном WebGL — фолбэк остаётся, пустого прямоугольника нет.
- Потеря контекста на живой сцене — появляется фолбэк «Контекст 3D потерян», сцена снимается;
  по «Повторить 3D» сцена поднимается заново (канвас + HUD возвращаются).
- Пиксельная проверка скриншотов: разброс яркости 27–37 (стд) и 900–1500 уникальных цветов в
  области сцены — пустого серого/белого блока нет (у пустого было бы ~0 и 1–3).
